The FFT command runs a discrete Fourier transform on the source trace array, then writes logarithmic magnitude values into the destination array. Any trace is limited to 601 points. Use FFT to convert zero-span amplitude-modulation data into the frequency domain; applying it to a frequency sweep does not produce time-domain information. The spectrum analyzer presents FFT output with a logarithmic amplitude scale. Along the horizontal axis, the left edge represents 0 Hz, while the right edge is Finax-; Fmax equals 300 divided by sweep time. For example, a 60 ms analyzer sweep time gives an Fmax of 5 kHz. The FFT algorithm models the sampled signal as periodic and assumes the analyzer sweep time contains an integral number of periods. With that assumption, the transform corresponds to an infinite-duration waveform made by concatenating time records. Actual measurements may contain a nonintegral number of periods in the record. In that case, the repeated records meet at step discontinuities. Those discontinuities create measurement error, including amplitude uncertainty, where small frequency changes seem to alter signal level, and reduced frequency resolution caused by filter shape factor and sidelobes. Windows are weighting functions applied to the input data so the record ends taper smoothly toward zero, which reduces the discontinuity and the resulting measurement errors.

 HP856Xx.marker_threshold

Set the minimum amplitude level that can qualify a trace peak for detection. The default setting is -130 dBm. The related `peak_excursion` command defines the excursion requirement. Peak excursion evaluation can include the part of a peak that falls below the threshold. For example, with peak excursion set to 6 dB, a peak that is 3 dB above the threshold is found if it extends at least another 3 dB below the threshold. Maximum 30 db to minimum -200 db.

Type: `signed int`

```python
instr.marker_threshold = -70
if instr.marker_threshold > -80:
    pass

```

 HP856Xx.peak_excursion

Define the trace behavior that qualifies as a peak. The selected value is the required monotonic rise followed by monotonic fall for a candidate to count as a peak.
For example, with peak excursion at 10 dB, both sides of the candidate must drop at least 10 dB before it is counted; see Figure 5-4.
The default value is 6 dB.
In linear mode, enter marker peak excursion as a unit-less number. Portions of a peak below the peak threshold also count toward the peak excursion requirement. For example, with peak excursion at 6 dB, a peak 3 dB above the threshold is detected when it continues at least 3 dB more below the threshold level.

Type: `float`


### Normalization

 HP856Xx.normalize_trace_data_enabled

Control normalization for stimulus-response measurements. The function subtracts trace B from trace A, offsets the result by the normalized reference position value (`normalized_reference_level`), and shows the result in trace A. â€˜normalize_trace_data_enabledâ€™ is intended to be used with `store_open()` and `store_short()`, or with `store_thru()`. Those commands store a reference trace in trace B; consult their command descriptions for details. Normalization is accurate only when both the reference trace and measured trace are visible on-screen. If either trace is off-screen, the instrument displays an error. For ERR 903 A > DLMT, adjust range level (RL) to bring the measured response inside the analyzer display range. For ERR 904 B > DLMT, calibration is invalid and a thru or open/short calibration is required. When active (ON), the â€˜normalize_trace_dataâ€™ command is automatically disabled by an instrument preset (IP) or at power on.

Type: `bool`

 HP856Xx.normalized_reference_level

Control the normalized reference level for use with the `normalize_trace_data` command. Using â€˜normalized_reference_levelâ€™ does not change the input attenuator or IF step gains. It acts as a trace-offset function, letting the displayed trace be shifted without adding hardware-switching errors to the stimulus-response measurement. The unit for â€˜normalized_reference_levelâ€™ is dB. In absolute power mode (dBm), reference level (`reference_level`) changes instrument gain and RF attenuation settings, which affects measurement or dynamic range. In normalized mode, meaning relative power or dB-measurement mode, NRL offsets on-screen trace data without changing gain or attenuation. This lets the normalized trace move on the display without reducing measurement accuracy through gain or RF attenuation changes. If the measurement range must be changed to put trace data on-screen, adjust the range level. In normalized mode, changing the range level affects instrument settings the same way reference level does in absolute power mode when normalize is off.

Type: `int`

```python
# reference level in case of normalization to -30 DB
instr.normalized_reference_level = -30

if instr.normalized_reference_level == -30:
    pass

```

 HP856Xx.store_open()

Store the current instrument state and trace A in nonvolatile memory.

Use this command together with `store_short()`, and run it before `store_short()`. Data captured during the store open procedure is averaged with data captured during `store_short()` to create an open/short calibration. For the calibration to remain valid, the instrument state, meaning the instrument settings, must not change between `store_open()` and `store_short()`. See the `store_short()` command description for additional details.

 HP856Xx.store_short()

Average the currently displayed trace A data with the previously saved open data, then store the averaged result in trace B.

This command is paired with `store_open()` and must be run after `store_open()` for correct behavior. See the `store_open()` command description for details. The open/short average trace state is kept in state register #8.
